# 节奏卡点剪辑 → 剪切点、节奏与变速

剪切落在哪里,和画面里是什么同等重要。本技能把一条曲目和一份简报变成
时间线上毫秒级的剪切点。

`motion-direction` 定能量;本技能把它变成网格与弧线。`motion-graphics`
承载这里点名的各调用的操作契约。`video-audio-continuity` 在还没有网格
可读之前,先决定音床从哪来:你自己加的一条轨,或一条承载全部场景的
生成片段。

## 网格要从音频来,不是从算术来

音床还不存在时,带着网格去生成它:Stable Audio 的提示词写明 BPM
(`stable-audio-prompting`),ElevenLabs 的 `composition_plan` 把每个段落的
长度钉到毫秒(`elevenlabs-audio-prompting`),drop 于是落在计划说的位置,
而不是模型随手放的位置。之后照样要测——生成出来的文件才是网格,提示词
不是。

对音乐片段跑 `detect_audio_events`,得到起音点与曲速。

- `onsets.times` 的单位是**秒**。时间线操作全部收毫秒,乘 1000。这是
  这里最常见的错误,没有之一。
- 搭任何建立在 `bpm` 上的东西之前先读 `tempo.reliable`。语音和环境底噪
  会凭空算出一个一脸可信的数字。不可信就直接用起音点。
- 第一个起音点就是网格的偏移。把网格锚在 0 而不是第一拍,每个剪切点
  都会早几帧——那种"差一点就对上"的剪辑感就是这么来的。

曲速可信时:

```
ms_per_beat = 60000 / bpm
frames_per_beat = (60 / bpm) × fps          # fps comes from get_timeline
```

120 BPM 时:每拍 500ms,30fps 下 15 帧,一小节 2000ms。取整要取**累计**
拍,绝不取步长,否则网格在长剪辑里漂移。

先把网格铺下来看得见,再把边缘吸附上去:

```json
{"op": "set_markers_from_beats", "onsets_ms": [0, 500, 1000], "count": 32}
{"op": "snap_to_beats", "targets": "all", "tolerance_ms": 60,
 "mode": "start", "action": "move"}
```

两者要么吃 `onsets_ms`,要么吃带 `offset_ms` 的 `bpm`。60ms 的默认容差
在 30fps 下约合两帧——宽到读起来"在拍点上",紧到不会把一个从来不挨着
某拍的边缘拖过去。`snap_to_beats` 会报告每个目标,包括没有任何东西够得
着的那些,并给出原因。`action: "move"` 保持片段长度、推移后面的内容;
`action: "trim"` 改变长度、不动邻居。标题必须落在某个冲击点上就用 move;
画面片段的出点必须接住下一镜就用 trim。

对于应该跟随速度变化的动画,在动画上存一个 `beat` 锚点:
`{index: 3, scope: "clip", offsetMs: -20}` 从片段开头数起;
`scope: "sequence"` 从文档速度的 `offsetMs` 数起。`index` 从一开始计,
`delayMs` 再叠加一个偏移。这不同于吸附片段边缘,也不同于烘焙实测音频曲线。
`animate_clip` 的工具输入不接受 `beat`;要写入动画的 `beat`,用
`set_timeline_document` 写整份文档。已存的动画需要 `id`、`role`、`preset`
和 `durationMs`;加 `beat` 时这些字段和动画的其余部分都要保留。写入时把
文档的速度、设置、媒体轨、模板标识、片段、轨道和标记一并带上。

## 按乐句剪,不按单拍剪

每一拍都剪一刀让人喘不过气,观众到第八拍就疲了。按 2、4 或 8 拍剪,第八
拍网格上的重音要克制使用。

| 性格 | 剪切间隔 | 转场族 | 变速 |
|---|---|---|---|
| 俏皮 | 4 拍,切分重音 | 硬切,偶用 `push` | 轻变速 |
| 高级 | 8–16 拍,长驻留 | 硬切,偶用 `crossfade` | 慢而平滑 |
| 商务 | 8 拍,平稳 | 只用硬切 | 无 |
| 爆发 | 高潮处 1–2 拍 | 硬切,`zoom`、`push` | 激进,卡在拍点上 |

把全片最大的那个视觉放在 drop 上。一条片子,一个峰值。

## 塑造弧线

均匀的节奏无论内容如何都读起来是平的。

| 阶段 | 剪切间隔 | 镜头长度 | 备注 |
|---|---|---|---|
| 铺陈 | 8–16 拍 | 最长 | 交代地点,让它呼吸 |
| 推进 | 8 → 4 拍 | 逐渐变短 | 加速蓄势 |
| 高潮 | 1–2 拍 | 最短 | drop、最大视觉、变速都在这 |
| 收束 | 一记长驻留 | 最长 | 峰值之后,片尾卡喘口气 |

## 藏起接缝

运动带着视线跨过剪切时,接缝是看不见的。在动作进行中剪,并让方向与
速度跨剪切匹配。图形则在变换峰值处剪——运动途中,不在静止点。

默认用硬切:同一轨上两个片段,严丝合缝地相接。别的手段只在有动机时
才伸手。

| 剪法 | 时间线上怎么做 | 什么时候用 |
|---|---|---|
| 硬切 | 相邻片段,无重叠,不设 `set_transition` | 十刀里的九刀 |
| 匹配剪切 | 硬切,两帧共享形状、位置或运动矢量 | 两个镜头押韵;动效设计里最有力的一招 |
| 叠化 | 进场片段设 `set_transition` `crossfade`,两片段至少重叠它的 `durationMs` | 同一场景的两个镜头 |
| 浸色 | `dipToColor` 配自己的 `color` | 章节切换 |
| 擦除/推/滑动 | 对应类型配 `direction`,指明进场片段从哪条边来 | 图形感,或横向能量 |
| 缩放 | `zoom` | 推进到下一拍 |
| J 切 | 下一镜的音频片段比画面早 4–12 帧开始,放在自己的音频轨上 | 对白、揭示:把观众往前拉 |
| L 切 | 当前镜的音频在下一镜画面下再跑 12–24 帧 | 场景转换、氛围声 |
| 甩切 | 短促的 `offsetX` 位移加硬切两侧各一段 `blur` | 起哄式高潮、场景跳切 |

引擎有两件事,不管你有没有要求它都会做:

- 同轨两个片段时间重叠时,重叠段自动叠化,无需任何调用。**意外重叠
  就是意外叠化。**想要硬切却看着发软时,先查 `startMs` 和 `durationMs`。
- 转场作用在进场片段的头部、压在它下面的东西之上。没有重叠,它下面
  就什么都没有,读起来是从黑场淡入。

J 切和 L 切靠把画面和声音拆到不同片段来搭,不靠转场:装配之后每镜的
孪生音频片段本来就在自己的音频轨上,挪那条片段,别挪画面。

## 变速

`set_time_remap` 把时间线时间映射到素材时间。`t` 在片段自己的窗口内跑
0..1,必须从 0 起、到 1 止、单调上升;`sourceMs` 说哪个毫秒的素材在那里
播放。`sourceMs` 递减是倒放,一对相同值是定帧。

冲着冲击点减速进、骤然出,最慢的一帧压在拍点上。一条 2000ms 的片段,
冲击点在 1200ms:

```json
{"op": "set_time_remap", "target": "Shot 3", "timeRemap": {"keyframes": [
  {"t": 0, "sourceMs": 0},
  {"t": 0.5, "sourceMs": 900, "easing": "easeIn"},
  {"t": 0.6, "sourceMs": 1000, "easing": "easeOut"},
  {"t": 1, "sourceMs": 2400}]}}
```

0.5 到 0.6 之间,时间线走 200ms 素材只走 100ms:冲击点上四分之一速。
`t` 出现重复或回退就是 `time_remap_not_monotonic`,一个错误。`split_clip`
和 `trim_clip` 拒绝已重映射的片段,因为重新推导曲线正是"一条斜坡变成另
一种运镜"的成因——先清掉重映射,剪切,再重设。

`set_clip_params` 的 `speedMultiplier` 是扁平替代:整条片段一个速率,
没有曲线。不需要起伏时用它。

要做节奏质感,`steppedTime: {fps}` 把单条片段的采样时钟量化;
`temporalEcho: {copies, intervalMs, opacityDecay}` 画出延迟的副本,
不用手工复制片段就能让尾迹拖过一个冲击点。片段的 `motionBlur` 为自己
的快门窗口设定 `samplesPerFrame` 和 `shutterAngle`。高于 1 的值是场景
采样数的下限请求;场景取所有请求中的最大值,封顶 32,并在各自的快门内
对每层均匀采样。这些字段要设在完整的时间线文档里;`set_clip_params`
会拒绝它们。

如果运动必须跟随真实音频包络或检测出的起振,用 `bake_audio_animation`。
它通过 `set_baked_animation` 写入一条带 `bakedFrom` 出处的、锚定源素材
的曲线;重新烘焙会替换那条实测曲线。拍点锚点则从文档速度重新计算时间,
而标记和 `snap_to_beats` 移动的是编辑点。

## 动手前先写计划

剪辑之前先把方案写下来,用操作真正吃的单位:

- 轨道规格:`bpm`、`fps`、第一个起音点(ms)、drop(ms)、每拍毫秒数。
- 四个阶段各自的毫秒区间与目标镜头长度。
- 每个剪切点写成绝对毫秒,配它的片段与剪法。
- 每个 J 切与 L 切的音频偏移(ms)。
- 每条变速写成它的 `t` / `sourceMs` 关键帧。
- 将要传给 `set_markers_from_beats` 的标记列表。

## 检查

每一批之后跑 `validate_timeline`:它抓重叠片段、比载体片段还长的转场、
短于一帧的片段。

然后看、然后听。在剪切点两侧各一毫秒跑 `preview_timeline_frame`,能看出
接缝是不是在你以为的地方;对音乐跑 `analyze_audio`,确认你建的网格与
文件吻合。宣布剪完之前跑 `render_timeline`——预览回答的是某个时码长
什么样,渲染回答的是它能不能播。

## 常见错误

| 症状 | 原因 | 修法 |
|---|---|---|
| 疯狂乱切 | 每拍一剪 | 按 2、4、8 拍的乐句剪 |
| 差一点在拍上 | 网格锚在 0,无视第一个起音点 | 用毫秒锚到起音点 |
| 长剪辑里漂移 | 逐步长取整 | 取累计拍 |
| 剪切生硬 | 放在静止点、两个动作之间 | 在动作中途剪,匹配方向 |
| 该硬却软 | 同轨片段重叠 | 修 `startMs` 和 `durationMs` |
| 转场从黑场淡入 | 进场头部下面没有东西 | 按转场的 `durationMs` 重叠两片段 |
| 全程发平 | 节奏均匀 | 铺陈、推进、高潮、收束 |
| 什么都不落地 | 没有唯一峰值 | 一个最大视觉压在 drop 上,随后一记驻留 |
