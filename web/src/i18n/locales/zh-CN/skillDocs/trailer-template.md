你是单个智能体。拿到片名、类型与时长,产出一份完整、带时码的预告片计划,并落成 NodeTool 分镜。你直接调用分镜、实体与时间线能力。你不搭工作流。除非被要求,不渲染、不装配。

先填表头。以下每个字段都是必填,且没有一个靠猜——没有的事实写 `[CLIENT INPUT NEEDED]`。

```text
TITLE:
GENRE:
LENGTH:           [seconds]
FORMAT:           16:9 / 2.39:1 / 9:16
THESIS:           [the one idea the trailer argues, one sentence]
CENTRAL QUESTION: [the question left OPEN at the end]
MOTIF:            [recurring visual element — hands, doors, water, mirrors]
                  Planted in SETUP, paid off in PEAK or BUTTON.
```

## 两条不可凌驾的原则

**事件 → 反应。**单位是一对镜头,绝不是单个镜头。有事发生,然后有一张
脸接收它。意义住在第二个镜头里。没有反应镜头的加码段是世界观铺陈,不是
加码。

**声音是夹具。**画面是断裂的——来自不同场景、地点与时间的镜头。声音是
贯穿全片的一条不断音乐底,正是这条底让碎片被读成一件事。绝不把声音切到
静音。压低它。

## 动态曲线

```text
  quiet / slow  ~65%          |  loud / fast  ~35%
  ─────────────────────────── DROP ──────────────────────
  Beats 1–4                   |  Beats 6–8
```

只有一个枢纽。骤降落在**全片约 65%** 处。其余一切都服从这条曲线。

**最小感知时长**——低于这些值,节拍立不住:

| 节拍 | 下限 |
| --- | --- |
| 骤降 | 1.0s |
| 铺垫 | 4.0s |
| 收束 | 2.0s |
| 任何反应镜头 | 0.8s |

**压缩规则。**低于 25 秒时比例会崩,所以短预告应该**融合**节拍,而不是
把八个全都缩小。融合顺序:钩子与铺垫合并 → 触发事件与加码合成一段递进 →
骤降原样保留 → 收束并入片名。

## 节拍预算

按片长换算时码,取整到 0.5s。取整后逐一对照各节拍的下限,有不足的按上面
的规则融合。

| 节拍 | 时长占比 | 职能 |
| --- | --- | --- |
| 1 钩子 | 0–8% | 打断。打开一个信息缺口。 |
| 2 铺垫/世界 | 8–25% | 建立认同。日常状态呈现为珍贵或脆弱。埋下母题。 |
| 3 触发事件 | 25–32% | 一个可命名的事件把状态变成问题。 |
| 4 加码/利害 | 32–65% | 累积。每个单元抬升一个新维度。最长的一段。 |
| 5 骤降 | 65–68% | 枢纽。最大对比,不是最大音量。 |
| 6 高潮/顶点 | 68–85% | 以碎片兑现。情感顶点是大奇观里的一个人味节拍。 |
| 7 片名卡 | 85–90% | 给这种感受命名。落在冲击上。 |
| 8 收束/刺点 | 90–100% | 近因效应。一个小而单一的节拍,脱离上下文也成立。 |

## 八个节拍

### 节拍 1 — 钩子

事件先于面孔。还没有类型标记。绝不解释。安静开场——开篇就响,会烧掉
骤降需要的动态余量。

| 类型 | 镜头 |
| --- | --- |
| 事件 | 一个带时间戳的现象——是**发生**的事,不是一种状态 |
| 反应 | 一张接收它的脸。是注意,还不是恐惧。 |

### 节拍 2 — 铺垫/世界

不是情节:是情感锚点。把日常状态呈现为珍贵或脆弱,否则它的毁灭毫无分量。
音乐母题在这里埋下,到高潮兑现。如果两个角色之后会冲突,现在就排一个
**分歧**节拍——否则他们的冲突是被断言的,不是被铺垫的。

| 类型 | 镜头 |
| --- | --- |
| 铺垫 | 主角处在日常状态——温暖、平凡、具体 |
| 铺垫 | 亲密或脆弱——一个微小的身体动作,埋下**母题** |
| 铺垫 | 分歧——两个立场,无言地摆出来 |

### 节拍 3 — 触发事件

一个可辨识的事件,绝不是蒙太奇。观众说不出什么变了,预告片就没有主轴。
第一次真正的冲击——它成立,是因为你此前一分未花。冲击是货币:花销要
递增。

| 类型 | 镜头 |
| --- | --- |
| 事件 | 转折——一个可命名的事件 |
| 反应 A | 角色 1 把它读作 `[reading A]` |
| 反应 B | 角色 2,**同一个**事件,读作 `[reading B]`——主命题的两张脸 |

### 节拍 4 — 加码/利害

累积,绝不重复。张力是时长的函数,所以这是最长的一段。揭示节奏像梯子
一样攀升,且永不抵达顶。**每个事件都要有接收者。**维度逐级抬升:
私密 → 社会 → 机构 → 家庭 → 个人。

| 类型 | 镜头 | 维度 |
| --- | --- | --- |
| 事件 | 规模扩大——世界注意到了 | 社会 |
| 反应 | 一张陌生人的脸 | |
| 事件 | 机构作出反应 | 国家 |
| 反应 | 主角的保护者做出回应——恐惧进入家庭 | |
| 事件 | 威胁进入家门 | 私密 |
| 反应 | 主角做出选择——一个越界的小动作 | |
| 反应 | 利害结晶——有人意识到自己失去了什么 | |

### 节拍 5 — 骤降

问题与承诺之间的枢纽。不是最响的时刻:是**对比**最大的时刻。你不是在
制造静默,你是在制造动态余量,而它必须落在一幅配得上这份压力的画面上。
低于 1 秒读起来像剪辑失误,不像停顿。

| 类型 | 镜头 |
| --- | --- |
| 骤降 | 静止。全片最好的一幅定格画面。小小的人影,巨大的未见之力。 |

### 节拍 6 — 高潮/顶点

以碎片兑现,绝不给答案。动能最高,但顶点是奇观内部的一个人味节拍——
没有脸的奇观只是噪音。是后果,不是结局。节拍 2 的母题以完整配器回归。

| 类型 | 镜头 |
| --- | --- |
| 高潮 | 那张脸——情绪上扬,可读 |
| **顶点** | 情感顶点——母题兑现,落到颗粒度的感官细节 |
| 反转 | 可选:一切骤然抽离——突然的缺席 |

### 节拍 7 — 片名卡

片名在情感电荷最大时到来,名字与感受焊在一起。它落在冲击**之上**,不是
之后——声音与字在同一帧。

### 节拍 8 — 收束/刺点

最后的东西才是被带走的。一次受控的释放,加一点让影片具体而非泛泛的
余味——在这里交代类型的真相。大场面之后要小而单一,且必须脱离上下文
也成立。进阶做法:把最大的揭示放在这里、片名之后,趁观众以为已经结束。

| 类型 | 镜头 |
| --- | --- |
| 收束 | 最后一拍——包袱、惊吓、温柔或揭示。拒绝观众预期的那一下。 |

## 音乐底 — 一条不断的轨

```text
[Hook]        sub-bass drone + ambience + ONE distant tonal element
[Setup]       THE SEED: fragile motif enters — instrument: [INSTRUMENT]
[Inciting]    motif bends. First impact. Sub grows.
[Escalation]  layers stack: pulses → riser → strings. Accelerating.
[Drop]        ★ DIP to bare sub-rumble. Never fully out.
[Climax]      THE HARVEST: motif returns fully orchestrated + choir/strings bloom
[Title]       one sustained luminous chord + sub-boom → title
[Button]      minimal. Withhold the stinger hit if the button is tender.
```

**切在瞬态上。**画面剪切落在打击点上,不落在两点之间。**冲击处声音设计
优先于音乐。**braam 扛住打击,配乐扛住情绪。

## 实体

出现多于一个镜头的任何角色都是**角色实体**,否则每次都是另一张脸。主角、
保护者与反应 B 的承载者,通常就是三个。反复出现的家是**场地**实体,调色
是**风格**实体,母题物(如果它是实物)是**道具**。

```js
import { list_entities, create_entity } from "@nodetool-ai/sandbox-nodetool/entities";

await list_entities({});   // reuse before you generate

const still = await nodetool.media.generateImage(
  "<the character, neutral background, in the trailer's grade>",
  await nodetool.models.pick("text_to_image")
);
await create_entity({
  asset_id: still.asset_id,
  kind: "character",
  name: "<Name>",
  descriptor: "<one to two dense sentences describing exactly what the reference shows>"
});
const entityId = still.asset_id;   // the entity IS its asset
```

描述词就是那张脸。在镜头的 `action` 或 `motion` 里用普通文本点名实体——
"Mara 转身离开窗边",绝不用 `@Mara`——也不要在镜头文本里重新描述他们。
渲染时只有当角色或道具的名字出现在某镜头的文本里才把它挂到该镜头上
(风格与场地实体总是生效),所以反应镜头写"她"而不写"Mara",渲染出来
就是一个陌生人。排节拍之前先把名单亮出来。

## 分镜板

### 1. 建板

```js
import { create_storyboard, edit_storyboard } from "@nodetool-ai/sandbox-nodetool/storyboards";

const board = await create_storyboard({
  name: `${title} — trailer (${runtime}s)`,
  brief: `${thesis}\nCENTRAL QUESTION: ${centralQuestion}\nMOTIF: ${motif}`,
  style: "<the grade in one line>",
  aspect_ratio: "16:9"
});
const boardId = board.storyboard_id;   // NOT board.id
```

### 2. 名单与模型

`edit_storyboard` 收五种操作:`add_shot`、`update_shot`、`remove_shot`、
`reorder_shot`、`set_board`。`set_board` 只接受
`{brief?, style?, aspect_ratio?, entity_ids?, image_model?, video_model?}`,
其余一律拒绝。模型来自 `find_model`——传各自结果的 `.ref`;没有默认值,
未设模型会让渲染失败。完整契约,包括每个镜头的提示词收到哪些实体,在
`commercial-beat-sheet` 的 § Tool contract 一节。

```js
const stills = await find_model({ capability: "text_to_image" });
const clips = await find_model({ capability: "image_to_video" });
await edit_storyboard({
  storyboard_id: boardId,
  ops: [{ op: "set_board", entity_ids: roster,
          image_model: stills.ref, video_model: clips.ref }]
});
```

每个结果还会点名一个 `prompting_skill`。在第 3 步之前加载它:镜头的
`action` 与 `motion` 就是生成器读的提示词(剪辑取 `motion` 在前、
`action` 在后),而预告片的反应镜头与骤降,面对要按顺序排节拍的
(Hailuo)、要分镜表的(Kling)或要声音简报的(Seedance)产品线,措辞
各不相同。

### 3. 每行一镜

节拍表里的每一行都是一条 `add_shot`。slug 承载节拍与类型,这样配对结构
得以进入分镜板和成片。

```js
await edit_storyboard({
  storyboard_id: boardId,
  ops: [{
    op: "add_shot",
    slug: "3-event",                     // <beat>-<type>: 1-event, 1-reception, 3-reception-a, 5-drop, 6-peak, 8-button
    action: "INCITING (0:09–0:10.5): the turn — <one nameable event>, Mara in frame",
    camera: { framing: "close", lens: "50mm", angle: "eye", movement: "static" },
    motion: "<what moves, with counts — 'she looks up once', not 'tense'>",
    duration_seconds: 1.5,
    render_mode: "keyframe"
  }]
});
```

镜头文本的规则:

- `action` 以节拍名与时码开头,然后是镜头。400 字符以内。
- 反应镜头的 `action` 点明这是谁的脸、读出了什么。它的 `motion` 是一个
  微小的单一身体事件。
- 骤降镜头的 `motion` 是明说的静止:"nothing moves except the water"。
- 片名卡与任何屏幕文字**不是**镜头。字在后期加(`caption-titles`),
  因为生成器写字不可靠。
- 只有重运动的高潮镜头用 `render_mode: "direct"`。反应镜头与骤降留在
  `keyframe` 上,脸才守得住。

### 4. 音乐底住在板上,不住在镜头上

把那八行底作为 `MUSIC:` 块写进板的 `brief`,每节拍一行、带时码。逐镜头
的 `narration` 保持为空——原生的逐镜头音频是碎片,正是夹具的反面。如果
板开在标签页里,`ui_storyboard_set_screenplay` 会把同样的文本写进
`musicPrompt`,`assemble_storyboard_timeline` 随即把它变成一条草稿音乐
片段。

## 交付前检查

给人看之前先跑一遍。每一行都必须对板成立,不是对计划成立。

- [ ] 钩子是事件先于面孔,无类型标记
- [ ] 每个加码事件都有反应镜头
- [ ] 铺垫把日常状态呈现为珍贵或脆弱
- [ ] 角色之后有冲突,就有分歧节拍在场
- [ ] 母题在节拍 2 埋下,在节拍 6 兑现
- [ ] 骤降落在约 65% 处,且落在一幅配得上这份压力的画面上
- [ ] 情感顶点不在奇观镜头上
- [ ] 片名落在冲击上,同一帧
- [ ] 收束小而单一,脱离上下文也成立
- [ ] 声音绝不切到真静音——只压低
- [ ] 核心问题在结尾仍然开放
- [ ] 没有节拍低于其最小感知时长
- [ ] 每张出现两次的脸都是板上的实体

## 渲染与成片(仅按需)

**先出静图。**`render_storyboard_stills` 只花几美分,而且你要逐张看。
脸错了在实体上修,绝不在单个镜头的提示词里修。

**每条剪辑都生成得长一些。**即使计划只要 1.5 秒,也让视频模型每镜出
4–5 秒——你要有帧可选——然后在时间线上修。`render_storyboard_clips`
没有时长覆盖,所以在渲染前用 `update_shot` 调大 `duration_seconds`,
事后再改回。镜头逐个渲染并静音各自的音频;修剪前用 `analyze_video` 读
每条剪辑的真实长度,因为模型对时长请求只是宽松地遵守。

**音乐底是一条片段。**`assemble_storyboard_timeline` 之后:

1. `generate_music` 一次,按完整片长、按那八行底生成。一个提示词,
   一条片段。
2. `edit_timeline` → `add_track`(音频),再 `add_media_clip` 把这条素材
   放在 0:00。删掉装配按镜头生成的所有草稿音频片段。
3. 对音乐底跑 `detect_audio_events`,然后 `beat-sync-editing`:每个画面
   剪切移到最近的瞬态。骤降镜头的入点落在压低处。
4. 压低是音乐底上的一个音量关键帧,不是剪切。绝不是一个空档。
5. 片名卡用 `caption-titles`,与音乐底中片名冲击同一帧对时。
6. `validate_timeline`,然后用 `preview_timeline_frame` 看骤降、顶点与
   片名。

`motion-graphics` 承载时间线操作契约,`video-audio-continuity` 处理某
镜头自带的声音必须留存的场合,`color-motion` 承载让不同场景的镜头剪在
一起的调色,`logo-reveal` 负责收束之后的厂标。
