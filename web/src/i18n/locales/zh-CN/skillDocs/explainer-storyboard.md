# 解说视频分镜 → 分镜 Agent

产出一份完整、可拍摄的解说节拍表,并落成 NodeTool 分镜。直接通过分镜与实体两组能力模块完成。不要搭工作流、不要跑管线。除非用户要求,不要渲染静图、剪辑或装配时间线。

## 如实的简报

建板前先收集这些事实:产品或功能、品牌与特质、品类、受众、核心问题、转折、2–4 个具体的机制步骤、证明素材、CTA、时长(30、60、90 或 120 秒)、平台、基调、必须包含的内容,以及禁用宣传点。核心问题、转折与机制是必填项。绝不发明能力、集成、数据、界面或客户。证明未经确认的地方,写 `[CLIENT INPUT NEEDED]`。

## 先定实体,后排节拍

每一个反复出现的人、场地、产品 UI、设备、比喻物、品牌标识与视觉风格都是一个实体。从 `list_entities` 开始;先用用户给的参考图与既有实体,再考虑生成。真实的产品截图是 `prop` 参考图,绝不重新生成。

先定风格实体。只为缺失的参考生成,并在生成其他每个实体之前套用该风格。一条典型的 60 秒解说片有 4–7 个实体:风格、人设、可选场地、产品 UI 道具、比喻道具。生成的 UI 标注为样机。

用 `create_entity` 配一段高密度视觉描述词。描述词写明精确的复现外观:角色的五官与服装;场地的材质与布光;UI 的布局、配色、字体与内容边界;比喻物的几何与材质;或风格的媒介、色盘、布光与焦段。实体 id 就是传给 `create_entity` 的素材 id。

## 教学弧线

按选定的时长换算时码,取整到 0.5 秒。使用这条弧线:

| 节拍 | 时长占比 |
| --- | --- |
| 问题 | 0–15% |
| 利害 | 15–25% |
| 转折 | 25–40% |
| 机制 1 | 40–55% |
| 机制 2 | 55–68% |
| 成果/证明 | 68–82% |
| CTA | 82–93% |
| 收尾 | 93–100% |

30 秒版本,合并问题与利害,机制只留一个节拍。90–120 秒版本,机制节拍至多三个。只用一个概念和一处直白的比喻。把视觉顿悟点放在转折进入机制的分界上,并在其后刻意留半拍静默。旁白至多 `runtime × 2.2` 个词。

## 交付物

按顺序产出:三个概念方向加一个推荐、完整节拍表、实体名单(id、种类、描述词摘要、关联节拍)。每个方向写明切入问题、比喻、顿悟点、契合度、风险与引用的实体。

每个节拍给出:时码、教学职能、构图、画面、动作、可见实体、逐字旁白、五个词以内的屏幕文字、确切的 UI/演示输入与输出(或 `NONE`)、音效、音乐、转场,以及它为什么教会人。机制节拍必须展示真实 UI 或带标注的样机。品牌标识留到转折之后才出现。旁白用动词,屏幕用名词。收尾呼应开头的问题。

## 落盘分镜板

用 `create_storyboard({ name, brief, style, aspect_ratio })` 建板。取 `board.storyboard_id`,绝不用 `.id`。把完整简报、选定的方向与实体名单写进 `brief`,项目日后才能复原。确切的调用形态与返回字段——实体 id 等于你传入的素材 id、五类 `edit_storyboard` 操作、`set_board` 接受什么——都在 `commercial-beat-sheet` 的 § Tool contract 一节;每个分镜类技能都对着那一节构建。

用 `edit_storyboard({ storyboard_id, ops: [{ op: "set_board", entity_ids }] })`
挂上名单 id(`set_entities` 只是 `set_board` 的别名)。在同一次操作里选定渲染模型:用 `find_model` 各查 `text_to_image` 与 `image_to_video`,各自结果的 `.ref` 写到 `image_model` / `video_model` 上,并在写镜头文本之前加载各自结果的 `prompting_skill`——镜头的 `action` 就是静图模型读的提示词,构图与板风格会被追加进来。

每个节拍用 `edit_storyboard` 加一条 `add_shot` 操作。高密度的 `action` 字段点名教学职能、方括号内的可见实体名、屏幕文字与 UI 演示。渲染时只有当人设或道具实体的名字出现在某镜头的文本里才把它挂到该镜头上(风格与场地总是生效),所以每个可见实体必须写进 `action` 或 `motion`,或列在那个镜头自己的 `entity_ids` 上。`action` 里的屏幕文字是给剪辑看的备注:装配后作为文字片段加上(`caption-titles`),不进渲染提示词。

到规划好的板为止,除非用户明确要求渲染或成片。汇报各方向、选定的板与实体名单。

## 渲染(仅按需)

先用 `render_storyboard_stills` 出静图——它们只花几美分——用 `view_image`
逐张看、问哪里不对,再用 `score_image_adherence` 对照镜头文本打分。人设
或 UI 样机漂移,在实体上修(描述词或参考图),然后重渲染用它的每个
镜头;构图失败,在该镜头的 `action` 里修。剪辑用 `render_storyboard_clips`;
静图对、剪辑错的片段,一次 `revise_storyboard_clip`。然后
`assemble_storyboard_timeline`。

## 当分镜板动起来

被要求成片时,`motion-graphics` 承载时间线工具契约,并分流到对应的手艺
技能:`video-audio-continuity` 决定各节拍渲染成一条剪辑还是垫在旁白轨下,
`caption-titles` 处理节拍表已写明的屏幕文字与标注,`frame-composition`
处理 UI 样机的摆位与它在 9:16 下是否成立,`motion-direction` 让机制节拍
共享同一种运动语言,`beat-sync-editing` 用于成片必须卡在音乐底上的场合。
顿悟点后的半拍静默是一次保持,不是一个空档——留在成片里。
