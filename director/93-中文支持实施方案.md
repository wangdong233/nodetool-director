## 1. 方案裁决:标准 i18next 基础设施 + 增量迁移(否决运行时字典)

| 候选 | 判定 | 理由 |
|---|---|---|
| **A. i18next + react-i18next + 命名空间 JSON**(采) | ✅ | 业界 React 事实标准(生态最大/文档最全/上游接受度最高);增量迁移=每个 namespace 独立 PR 可评审;runtime 字典方案因"上游会拒 hack"被用户转向直接否决 |
| B. 运行时字典 walker | ❌ | 解耦约束已解除;上游贡献场景下 DOM/文本 walker 属 hack,PR 必拒 |
| C. 仅 MUI locale | ❌ | 覆盖面结构性残缺(MUI 只管自家组件内部文案) |
| D. 浏览器翻译 | ❌ | 不可控词表/需用户手工操作/不算 in-repo 支持 |

**上游可贡献性设计**(硬要求,贯穿全部实现):
- 默认语言=**英文**(护 ~1533 处单测断言+~86 处 e2e 选择器+上游 BRAND.md 词表治理;PR 不改变任何英文默认行为)
- 上游 PR 形态=**基础设施+种子词表+迁移指南**(≈15-25 文件的可评审增量),绝不做一次性 5000 串大爆炸 PR
- 全部 i18n 文件集中在 `web/src/i18n/`(新目录,上游零历史冲突)+ 覆盖面组件的逐文件 t() 化(该部分上游冲突本就随季度重写常态存在,已是接受面)

**上游 PR 内容清单**(R2 补,按仓库自身规则倒推):
- **键名约定=结构化键**(`nav.settings.title` 式,非英文原句自然键)——上游季度重写 96% 文件,英文原句一改键即死;结构键只随 UI 结构变化
- **en 为源真本 + 缺键回退策略显式化**(zh 缺键→回退 en 值,原始键串禁入 DOM)
- **CI 完整性闸**:en↔zh 键集奇偶校验进 `npm run check`(缺键即红)
- **依赖论证块**(DEVELOPMENT_STANDARDS §21 格式):i18next+react-i18next(选型理由=本仓 React19/Jest/Vite 无 SSR 全兼容;react-intl 的 ICU 复数 zh 无需求;lingui 编译插件对 Vite 8 过新)
- **文档同 PR 更新**:BRAND.md 加 zh 词表治理节、web/src/AGENTS.md 加 i18n 约定、web/TESTING.md 加语言隔离规则

## 2. 技术设计

```
web/src/i18n/
  index.tsx            # i18next init + I18nextProvider + useAppI18n hook + 语言切换/持久化
  locales/en/<ns>.json     # 英文源(与现文案逐字一致=零行为变化)
  locales/zh-CN/<ns>.json  # 中文(多轮润色产物)
  glossary.md          # 术语表(润色飞轮的锚,单串改词必先过表)
```

- **命名空间**(首批,按使用频率):`common`(全局按钮/状态词)→ `nav`(侧栏/顶栏/菜单)→ `settings`(设置各面板)→ `editor`(节点编辑器高频 UI)→ `chat`(对话面板);后续 `timeline`/`storyboard` 等按同模式增量
- **语言检测**:localStorage `nodetool-language`(**Y2 修正:kebab-case 对齐仓内既有键**)→ navigator.language → 兜底 en;切换即时生效(i18next 内建),同步 `document.documentElement.lang`;init 直读该键,SettingsStore 不镜像(避免扩散 diff),切换器经 i18next 订阅自反映
- **切换器落位**(Y1 补):`menus/SettingsMenu.tsx` 的 general 节(+ `settingsSearch.ts` 的 SETTINGS_TAB_ITEMS/TAB_LABEL 同批 t() 化登记);RailAppMenu 的 Settings/Help/Downloads 词条随 nav namespace
- **打包策略**(Y3 补):en 词表 eager(默认零变化);zh 按命名空间 dynamic import 切换时懒载——守 web/src/AGENTS.md 编辑路由 ≤250KB gz 初始 JS 预算
- **MUI**(R1 修正):`zh-CN` 激活时 `createTheme(options, zhCN)`(自 `@mui/material/locale`,接在 `web/src/components/themes/ThemeNodetool.tsx`,挂载点=`ThemeRoot`/`index.tsx`)。**不引** `@mui/x-date-pickers` 的 LocalizationProvider——本仓无日期选择器/无 TablePagination/DataGrid(评审核实),禁为零收益依赖
- **不翻译面**(诚实边界):后端驱动的节点标题/描述/属性名(上游节点英文,我们渠道已中文——正是"数据即多语言"的正确形态)、动态后端错误串、日志
- **必须覆盖面**(R3 补,评审抓漏):①**日期**——`utils/formatUtils.ts` 的 `Intl.DateTimeFormat(undefined,…)` 改为注入 app locale(en 输出字节不变);`utils/dateFormat.ts` 的 `MONTHS_SHORT` 硬编码 Jan-Dec 改 locale 化(喂 VersionHistory/WorkflowList 等可见 UI)②**Tabulator**——`node/DataTable/DataTable.tsx` 实例化时传 `locale`(内置 zh-cn 语言包)③**aria-label**(212 文件,随覆盖 namespace 的组件同批 t() 化——zh UI 配英文读屏=WCAG 回退)④**启动屏文案**(index.tsx Loading/错误屏)
- **html lang**:`index.html` 保持 en,由运行时切换器更新(上游 PR 零 diff 于 index.html)
- **测试隔离铁律**(Y4):zh 测试文件 afterEach 必须 `changeLanguage("en")`+清 `nodetool-language`(RTL cleanup 不重置 i18next,不还原则毒化同文件后续用例);新增四类测试:缺 zh 键回退 en 且键串不入 DOM/切换跨 reload 持久/`documentElement.lang` 同步/隔离规则本身
