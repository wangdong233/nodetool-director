# 98 · 后端模板目录中文化专项报告

> 用户令(2026-09-29):各项实施完毕后,详细具体报告"后端模板目录"是什么问题。本报告 = 现状定谳 + 数据盘点 + 三方案对比 + 建议。

## 一、它是什么:不是缺陷,是一个未立项的数据域

战役期间 dashboard/workspace/examples 页浏览器扫持续看到英文的 **Ad Maker / AI Spokesperson / Beat sync editing / "Turn a Support Thread into a Bug Report"** 等,曾被误判为"未接线"。定谳:这些字符串 **在 web/src 中不存在源码**——它们是随产品发布的示例内容(JSON 数据文件的 `name`/`description` 字段),由后端 tRPC(读盘)原样返回,前端按"后端数据透传"渲染。登记表 §3 由此立案为可辩护;但它们**用户高度可见**(首屏、示例库、节点库面板),是否中文化是产品决策,不是 bug 修复。

## 二、数据盘点(实测)

| 目录 | 路径 | 数量 | 内容 | 用户可见处 |
|---|---|---|---|---|
| 小程序目录(apps) | `packages/base-nodes/nodetool/examples/apps/*.app.json` | **24 个**(内含 65 条工作流) | name+description(营销文案,共 ~3.8k 字符) | 工作台"从小程序开始"、示例页主卡 |
| 示例工作流(nodetool-base) | `.../examples/nodetool-base/*.json` | **194 个** | name+description(共 ~37k 字符,即页面"194 examples") | 示例页列表、节点库"配方"面板 |
| 合成示例(compositions) | `.../examples/compositions/` | 6 个 | 同上 | 示例页 |
| 分镜示例(storyboards) | `.../examples/storyboards/` | 3 个 | 同上 | 示例页 |
| 配方(recipes) | `.../examples/recipes/` | 7 个 | 步骤+描述 | 工作台"快速上手" |
| 技能卡(skills) | (节点库内嵌) | ~10 组 | 标题+长描述 | 工作台"选择一个技能开始"区 |

合计需译文本量:**~260 个条目 / 约 45k 英文字符**(约等于本次 web 战役已译量的一半)。数据文件格式:`{schemaVersion, name, description, app, workflows}`——**文件名即稳定 id**(ad-maker.app.json → "ad-maker"),这是中文化方案的锚点。

## 三、三方案对比

### 方案 A:前端词典按 slug 映射(推荐)
前端建 `examples` 命名空间,键 = 文件名 slug(`examples:apps.ad-maker.name/.description`),渲染点 `i18n.t(key, { defaultValue: serverName })`——与战役已固化的 **labelKey 模式完全同构**,零后端改动、零 API 契约变化、上流同步零冲突(示例 JSON 更新时 defaultValue 自然兜底)。
- 成本:前端 4 个渲染点改造(DashboardTemplates/DashboardExampleApps/DashboardRecipes/NodeLibrary 配方面)+ ~260×2 词条翻译(一个 agent 批次约 1-2 小时)。
- 缺点:翻译放前端词典,后端/CLI/API 消费方仍读英文(本仓库无此诉求)。

### 方案 B:后端双语字段
app.json 加 `name_zh/description_zh`,API 按 `Accept-Language` 或查询参数返回。语义最正(数据本体多语),但改动面大:协议 schema、tRPC 路由、文件格式版本、上流合并冲突高发(每个示例文件都会被触碰)。**不建议**——为一个展示层需求动数据契约,过度设计。

### 方案 C:保持英文
理由:示例库本质是"产品示范内容",英文在国际开发者工具中常见;且部分名称(Ad Maker/Model Arena)近品牌词。**代价**:中文用户的首屏主视觉区仍是英文,与全站 zh 体验割裂——与本次战役目标冲突,不推荐作为终态,但可作为"暂缓"决策。

## 四、建议与边界

1. **建议方案 A**,作为独立批次(不混入 web 战役收尾):一个 worktree agent + `examples` 新命名空间,复用 G1-G4 闸门与页面驱动验证(改完直接扫 dashboard/examples 页确认)。
2. 翻译口径:名称可半保留品牌感(如 "Ad Maker(广告制作器)" 或意译"广告制作器"),描述按营销文案译;**需你拍板名称策略**(保留原名 / 括注 / 意译)。
3. 不在本次战役计"未完成"——它是数据域新项目,边界已在登记表 §3 立案。

## 五、验证附录

- 目录计数命令实测(2026-09-29):apps 24 / nodetool-base 194(描述 37,081 字符)/ compositions 6 / storyboards 3 / recipes 7。
- 服务链路:`examples/workflows.ts` 读盘 → tRPC workflows/applications 路由 → 前端 `DashboardTemplates` 等直接渲染 `name/description` 字段(web/src 无这些字符串,grep 零命中——战役中"找不到源码"的疑团由此解开)。

## 六、用户裁决(2026-09-29)

**采用方案 C:模板目录保持英文。** 本报告归档,方案 A/B 不再立项。
