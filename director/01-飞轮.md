# 01 · 开发飞轮规约(v1)

> 本文件是循环迭代的执行宪法,**每轮迭代后依 §7 复盘修订本文件本身**(版本号随迭代前进)。内核结构 = three-phase-workflow(研究→评审→实施)+ 02/03 架构与审查清单 + Gauntlet 式对抗评审。

## 1. 迭代结构(七相,顺序闸门)

```
N 轮: [0 复盘] → [1 研究] → [2 方案] → [3 实施] → [4 验证] → [5 提交] → [6 归档]
        ↑____________________ 飞轮自审(§7)驱动下一轮参数 ____________________↓
```

| 相 | 内容 | 准出 |
|---|---|---|
| 0 复盘 | 判定 N-1 轮:DoD 逐项 green/partial/red+证据;指标(测试通过率/mutation/审查发现/磁盘写/耗时);飞轮自审(§7) | 迭代报告 `iterations/NN.md` 落盘 |
| 1 研究 | 并行 scoped agent 白盒探查(路径限定本仓,题目不重叠;上游漂移重验) | 研究简报(带 file:line 证据) |
| 2 方案 | 设计文档→两轮自查(需求覆盖/可行性)→fresh-agent 对抗评审(03 §3.7 耦合对枚举+§0.5 面清单;A/B 选择走 §0.4 盲选二元裁决) | 零 blocking finding |
| 3 实施 | worktree 隔离多 agent 并行;新包 TDD(先失败测试) | 实现完成+自测绿 |
| 4 验证 | P0=build+单测**连续两遍全绿**+lint+CI-parity(空 HOME);P1=真机验证(画布 UI 走 lasso 真浏览器);02 清单 scoped 跑;涉 CI 配置者以**远程 CI 实际结论**为准 | 全绿 |
| 5 提交 | 合并 main→push→回查远程 CI 结论(2.6) | 远程绿 |
| 6 归档 | 文档同步/基线回填/本轮迭代报告 | 报告含 §7 自审段 |

**停机条件**:宪章 §3 的 R1-R4 全部 DoD green + fresh-agent 终审(盲选二元,PASS/BLOCK)+ 覆盖面清单(§0.5)核对 + 用户交付确认。缺一不停。

**升级规则(两击定律)**:同一缺陷两轮修复失败 → 强制停止单点修补,重述目标(换路径或升级用户裁决),禁止第三轮同路径硬闯。

## 2. 里程碑序列(映射宪章 R1-R4)

M0 仓库与基线 → M1 本地起跑(npm/build/dev/canvas 可达) → M2 零代码三连(智谱端点/MCP 挂入/CC 反向) → M3 mediagen-nodes v1(首批渠道 factory+manifest + pixverse 确认对 + vitest) → M4 credit 预算闸 → M5 端到端一条链 mp4 → M6 解耦双演习(上游同步/新渠道 manifest-only) → M7 Windows 兼容与部署文档 → M8 性能基线 → M9 收尾(文档整理+教训回流+终审)。

顺序允许交错(M6 演习可提前至 M3 后任意轮触发一次真实 upstream merge),但 R1-R4 的 DoD 只能在其里程碑验收。

## 3. 验证纪律(03 摘要,冲突以 03 原文为准)

- producer 契约:每处外部字段读取须 L1/L2 证据(渠道 wire 契约报告 = L1 基准);缺字段→undefined 语义必须显式。
- 测试必须能失败:新测试以破坏生产代码验证会红;断言期望值禁从实现输出反推(§2.1 项 10)。
- mutation:自建包改动 mutation score ≥80%(Stryker 起步,CI 起来后入 lane)。
- 环境假设:本地绿≠CI 绿;涉 CI/测试改动以远程结论为准;空 HOME 复跑为常备命令。
- 时序类缺陷:无插桩真机复现一次(Heisenbug 纪律)。
- UI 改动:lasso 真浏览器点验 + 截图证据。

## 4. 多 agent 纪律

- builder 不自审:审查/终审一律 fresh agent(无构建上下文)。
- 并行实施互不共享 worktree;每个 worktree 一个明确 DoD。
- 长命令一律后台+轮询(防 stall);派只读 agent 的 prompt 里显式禁写盘。
- 审查返回 schema 强制:`{verdict:'PASS'|'BLOCK', findings:[{severity, location, evidence, why, fix}]}`;对比类 `{pick:'A'|'B'|'both-reject', why}`。

## 5. 磁盘写监控协议

- 常驻 iostat 采样(仓外日志)+ 阶段边界 `diskutil activity` 差分,写入 `director/logs/disk-ledger.md`(每迭代一节:阶段/写入GB/预算对比)。
- 单命令预计 >2GB 写入先登记后执行;超标(单迭代 >5GB)必须在迭代报告列根因与下轮减写措施。

## 6. 上游同步策略(04-基线 hook 清单配套)

- main 定期 `git fetch upstream && git merge upstream/main`;合并冲突只允许出现在**已登记 hook 点**,出现在自建域外的未登记文件 = 收敛面违规(回 §2 方案相重新设计)。
- 每次真实 merge 顺手完成一次 M6 性质的演习记录(upstream 前进多少/冲突点/解决方式/测试结论)。

## 7. 飞轮自审(每轮强制,迭代报告内成节)

逐项回答并落到下一轮参数:

1. 哪个闸门**最晚**发现问题?该问题本应在哪一相被抓住?→ 把检查前移到该相。
2. 本轮有无返工(rework)?根因是研究不足/方案错误/实施失误/环境假设?→ 对应相加检查项。
3. 磁盘写/耗时/token 是否超预算?→ 减写/提效措施。
4. 两击定律是否被触发?触发则该缺陷升级处理是否完成?
5. 里程碑 DoD 判据本身是否被证明不可度量/度量错误?→ 修订宪章 §3(显式记录修订)。
